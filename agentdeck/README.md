# AgentDeck

多 CLI 终端聚合器 + LoopForge 工作流看板。桌面版 = **Go daemon + Electron 外壳**。

```
Electron 外壳 (main.js / preload.js)
        │  拉起、探活、提供目录选择
        ▼
agentdeckd.exe  (Go, 127.0.0.1:3210)
        │  托管界面 + PTY + 工作流扫描 + 阶段编排
        ▼
浏览器界面 (ui/, 也是普通网页)
```

daemon 在 `E:\googledown\agentdeckd`，本目录只有外壳。

## 项目首页与终端

- **项目首页 = 看板**：左侧点项目进入它的专属看板，只显示当前项目的任务，与其他项目隔离。
  页面上下各半：上半是四条泳道（排队 / 进行中 / 需要你 / 已完成），
  下半是选中任务的阶段流程图 + 启停操作 + 各阶段 CLI 选择。
  卡片显示当前阶段、进度条、执行 CLI、耗时，运行中的卡片还会实时显示终端最后几行输出。
- **终端在左侧目录**：所有跑着的终端（含流水线拉起的）都列在项目下的「终端」里。
  点某个终端才进入它的对话页（xterm + 右侧工作流阶段图），点项目名或「← 看板」回到看板。
  流水线拉起的终端标题是「阶段 · 任务」，一眼能看出它属于哪个工作流。
- **CLI 品牌头像会跟着进度走**：终端列表和标题栏显示该终端对应 CLI 的动态头像
  （运行中跳动 + 光环，等待是琥珀色呼吸，失败变红）；看板卡片的当前阶段、
  阶段流程条、右侧阶段图的每个节点也都有对应 CLI 的头像。阶段流程图上还有一个
  「跑者」头像，阶段推进时从上一个节点跳到下一个节点，暂停 / 出错 / 完成时换成对应状态色。
- **工作流列表**：项目下的「工作流」列出该项目的所有任务（排队 / 进行中 / 已完成都在里面），
  不是只显示已完成的；点任意一条会选中它并打开看板。
- **项目「⋮」菜单**：点项目行右侧三个点是二级菜单，里面才有「移除项目」，选中后还会弹确认框
  （取消 / 移除），确认只从列表移除，不删磁盘目录。
- 支持 44 款 coding agent CLI（Claude Code、Codex、Gemini、Qwen、opencode、Cursor、Copilot、Kimi、Aider…），
  新建终端时可直接按名字搜索，已安装的排前面。

## 工作流 → 终端

左侧「终端」「工作流」两个分组旁边不再有「+」按钮，终端由工作流自动带出来：

1. 看板右上角点「新建流水线」，写需求、给 6 个阶段各选一个 CLI，点「启动」。
2. daemon 在下一个调度周期（约 2 秒）拉起当前阶段的终端，页面会自动切到该终端页。
3. 每个阶段都是独立终端（独立进程、独立上下文），阶段之间靠 `artifacts/<slug>/` 里的
   黑板协作：产物文件 + `.agentdeck/handoff/<STAGE>.md` 交接包。所以 6 个阶段 = 6 个终端，
   跑完一个就归档日志、关掉终端；只有同一阶段被打回返工且原终端还活着时才复用。
4. 一个任务跑完（`workflow_completed`）后，流程底部出现「新建任务」按钮，点它直接开下一条流水线；
   上一条会留在看板「已完成」泳道和左侧「工作流」列表里，可以随时回看或「重新启动」。

## 设置（左下角）

顶栏只保留 **文件 / 视图** 菜单和右侧的窗口键；原来的「CLI 设置」「工作流」统一收进左下角的
**设置** 按钮，弹窗左侧是竖向页签，右侧是内容：

- **终端 CLI**：逐款 CLI 配置路径、参数、npm 包、启用状态，以及版本检查。每行还会标出该 CLI
  在 6 个阶段（需求 / 方案 / 开发 / 审查 / 测试 / 沉淀）的适配度和「最擅长」的阶段，顶部可按
  阶段筛选；行尾「更新内容」打开右侧抽屉，显示最新版本发布说明的中文译文，可切换英文原文。
  顶部「一键更新 N」会把所有可升级的 CLI 依次更新到最新版并自动刷新版本号，「刷新版本」
  强制重新探测全部版本。
- **工作流**：右侧工作流面板的显示开关和「打开」按钮。
- **外观**：分「软件配色」和「终端配色」两组。软件配色有 9 套整包配色，分浅色和夜间：
  浅色是紫罗兰 / 海盐蓝 / 苔原绿 / 暖陶橙 / 樱花粉 / 石墨灰；夜间是深空 / 午夜蓝 / 松林夜，
  整包转深色（含滚动条、输入框等原生控件）——画布、卡片表面、边框、强调色和语义色一起切换。
  终端配色有 6 套（暗夜 / 石墨 / 紫夜 / 深海 / 暖沙 / 纸白），只改终端内容区，和软件配色互不影响。
  两组选择都即时生效并记在 `localStorage`。

逐款 CLI 的配置项：

- **路径**：指定可执行文件（例如换成本机的 `claude.cmd`）；留空 = 自动探测。
  探测会按 `PATH` + `PATHEXT` 查找，并兜底 npm / bun / `~/.local/bin` 目录。
- **参数**：追加的默认参数；留空 = 沿用内置参数（例如 Claude Code 的 `--dangerously-skip-permissions`）。
- **启用**：取消勾选即临时停用，新建终端里会置灰，流水线调度到它会直接暂停并提示。
- **版本**：每行显示本机版本（`--version` 探测）和 npm 上的最新版；有更新标「可升级 vX」，已是最新标「最新」。
  顶部「检查版本」可强制重新探测；结果缓存 10 分钟，改路径/参数后自动失效。
- **npm 包**：该 CLI 对应的 npm 全局包名，留空 = 用内置默认或本机全局安装检测到的包名。
- **安装 / 更新**：未安装的 CLI 每行都有「安装」按钮，没有包名时先弹出输入框补一个，再后台跑
  `npm install -g <包名>@latest`；有更新时显示「更新」——npm 全局安装的走 npm，自管理安装的
  （例如 pi 的 `~/.pi`）跑它自带的 `pi update`。任务面板逐行显示输出，可随时取消，成功后自动重新探测版本。

## 窗口外壳

Electron 窗口是无边框的，标题栏和窗口键由页面自己画：

- 左上角是品牌图标 + **文件 / 视图** 菜单，和界面同一套配色。
- 右上角是最小化 / 最大化（还原）/ 关闭，关闭键悬停变红。
- 浏览器里直接打开 `http://127.0.0.1:3210` 时，菜单和窗口键自动隐藏。

修改即刻保存在 `%APPDATA%\agentdeckd\config.json` 的 `cliOverrides` 里，
新开的终端和流水线立即生效；每行的 ↺ 恢复默认。设置页支持搜索，顶部显示 `N/44 可用`。

## 阶段编排

看板可以按阶段分配不同 CLI：需求交给 Claude Code、方案交给 Codex、审查交给别的模型都行。
驱动模式下每个阶段独立开终端，角色规则（architect / developer / code-reviewer …）和交接包
在启动时注入，阶段之间不共享对话历史，只通过 `artifacts/<slug>/` 黑板传递产物和交接文件。
阶段声称完成但黑板上的文件不存在或为空时不会推进；本阶段缺少六节齐全的交接包
（`.agentdeck/handoff/<STAGE>.md`）也会暂停；被打回过的阶段重跑后，产物必须是本次
派发之后新写的，否则按「旧产物冒充返工」暂停。审查 / 测试失败会沿回退边打回开发，
超过 `maxReworks` 轮后停下等人工处理。暂停时可以用流程底部的「打回返工」把当前阶段
退到任一上游阶段并填写原因，原因会写进下一轮返工提示；点「继续」则先复查门禁，
仍不通过就重跑当前阶段。CLI 长时间不写状态会标成「等待你输入」，在「需要你」泳道里提醒。
驱动中的任务会写 90 秒运行租约，另一个 AgentDeck 实例正在驱动同一任务时会拒绝启动，
需要显式「强制接管」。

## 运行

```bash
# 1) 先编 daemon
cd E:\googledown\agentdeckd
set PATH=E:\googledown\toolchain\go\bin;%PATH%
set GOPROXY=https://goproxy.cn,direct
go build -o agentdeckd.exe .

# 2) 再起外壳
cd E:\googledown\agentdeck
npm install
npm start        # 会自动拉起 ../agentdeckd/agentdeckd.exe
npm run dist     # 便携版 exe（daemon 打进 resources），产物在 dist/AgentDeck-<版本>-portable.exe
```

也可以不开 Electron，直接浏览器访问 `http://127.0.0.1:3210`。

## 版本

- `package.json` 的 `version` 就是窗口标题和「设置 → 关于」里显示的应用版本
- 正式发版由 CI 从 tag 写入（见仓库根目录 `RELEASE.md`），本地手动打包前记得和
  `../agentdeckd/version.go` 保持一致
- 应用内更新：daemon 查 GitHub Releases，标题栏出现「vX.Y.Z 可用」后，从「关于」下载新的
  `AgentDeck-<版本>-portable.exe` 替换原文件即可；配置在 `%APPDATA%\agentdeckd`，替换不丢

## 界面

```
┌──────────────┬──────────────────┬─────────────────┐
│ 项目      +  │                  │ 工作流          │
│ ● dianqi     │                  │ 阶段图          │
│    终端   +  │   终端 (xterm)   │                 │
│     ○ claude │                  │                 │
│    运行   +  │                  │                 │
│     ⑂ TASK-1 │                  │                 │
│     ! TASK-2 │                  │                 │
└──────────────┴──────────────────┴─────────────────┘
```

- 终端按工作目录归属到项目，不在任何项目下的落到「其他终端」
- 状态图标：琥珀旋转=进行中，红 `!`=失败/打回，绿色分支=完成，空心圈=未开始
- 关掉窗口 daemon 继续跑，重开自动接回会话（输出回放）

## 限制

- 桌面壳只有 Windows（ConPTY）；Linux 服务器不装桌面壳，直接跑 daemon + 浏览器
- 未做代码签名，首次运行会弹 SmartScreen
- LoopForge Local 官方安装器只支持 claude / codex / cursor / codebuddy / pi / dsh / hermes；
  看板编排不走官方安装器，直接驱动各 CLI 的原生终端，所以其他 CLI 也能用，只是没有 LoopForge 的 slash 命令文件
- TUI 是否接受“启动后注入的文本”取决于各自 CLI；registry 里标了 `after-start` 的都已按这种方式设计
